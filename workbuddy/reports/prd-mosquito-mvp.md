## 1. 产品目标（三个清晰、正交的目标）

- **G1（效率）**：将单 zone 处理的人工作业时间从"手动标屋顶数小时"压缩到"网页内快速标注 + 一键处理 < 15 分钟" [假设，来自用户研究痛点]。
- **G2（闭环可信）**：在免费云上提供"上传→处理→复核→多格式报告→实时监控"一站式闭环，每个低置信框带"待复核"状态，结果可追溯。
- **G3（域专属精度）**：YOLOv13n 自训模型针对城中村密集屋顶适配，首版以置信度双线（高>0.8/低<0.5）输出可验收检测结果，并为趋势分析预留 zone_id + 时间戳。

三者正交：G1 关注操作成本，G2 关注流程与信任，G3 关注识别质量与数据资产。

## 2. 用户故事（场景）

- **US1（飞手）**：作为无人机飞手，我在 80m 高度按 zone 编号系统俯拍城中村屋顶，传输图像后能在网页看到"已接收"状态，确保不丢数据、参数标准化。
- **US2（操作员）**：作为平台操作员，我在一站式网页内用简化标注框出屋顶范围 → 点"提交任务" → 通过实时进度面板观察处理 → 对低置信框标记"待复核/确认" → 下载标注图与报告，尽量少手动。
- **US3（疾控中心工作人员）**：作为疾控中心工作人员，我打开 HTML/PDF 报告，一眼看到高风险 zone 与高密度网格，依据标注图定位现场清理点，报告可打印/转发，可直接用于防控考核与向上级汇报。
- **US4（研究生/MVP 开发者）** [假设]：作为兼任开发的操作员，我能在 README 指导下于本地或 HF Spaces 一键部署跑通整条链路。

## 5. 数据依据（来源：数析 / data-analyst；含冲突参数）

**确定性参数（PRD 阶段先定死）**：H=80m；原始图 4000×3000；单 zone 覆盖 120×90m；GSD≈3cm/像素（自洽，120m/0.03=4000px ✓）；置信度双线（高>0.8/低<0.5）；最小 3 类（绿植/水桶/花盆，示例待确认）；输出物全包含。

**派生指标 [文档设计值]**：单 zone 网格数（grid 640, step 576）→ cols=7, rows=6, 共 42 网格/zone，重叠率 10%；单网格地面足迹 19.2×19.2m，小容器（<6–9cm 实物）有漏检风险需实测。

**冲突/待确认参数**：
- 网格尺寸 640×640（配 YOLO）vs 800×800（暂定）[冲突]
- 屋顶判定阈值 ">50%→c1" 但括号写 "10%？" [冲突]
- IoU 去重 0.3–0.5（打？？？待确认）
- 置信度过滤中间值未给（文档仅给双线阈值，0.5–0.8 之间如何处理待确认）
- CPU 推理可行性（暂定，待实测）
- 真实 GSD / 相机型号（待确认）

**必须固化最小参数集（下一步拍板）**：①网格尺寸 640 或 800；②屋顶判定阈值 50% 或 10%；③IoU NMS 建议先 0.45；④置信度线低 0.5 高 0.8；⑤CPU 推理实测；⑥真实 GSD/相机型号；⑦最小类别是否锁 3 类。建议：网格尺寸/重叠/IoU/屋顶阈值做成可配置项，首版用建议值跑通，真实数据回灌后调优；IoU 与屋顶阈值属冲突项，必须首版内测前锁定。

## 7. 关键流程图 / UI 设计稿

端到端流程（MVP 纯 HTML 单页）：
```
飞手拍摄 → [传输/上传] → 网页标注屋顶(R1)
  → 一键提交(R2) → 实时面板(R7)
       ├─ 网格裁剪 c1/c2
       ├─ YOLOv13n 推理(R3)
       ├─ 坐标映射+NMS(R4)
       ├─ 标注图(R5)+JSON(R6)
       └─ 复核低置信框(R9)
  → 报告 HTML/PDF(R8) → 监测人员决策
```
页面结构：①上传页（zone 图 + 元数据）②标注页（画布 + 工具栏）③进度面板页（步骤条 + 百分比）④结果页（标注图 + 待复核列表 + 下载按钮）⑤报告页（报告嵌入 + PDF 下载）。

## 8. Non-goals（明确不做什么）

- 不建 PostgreSQL/Redis/队列/监控系统（改用 SQLite + 本地/免费云存储 + 进程内状态）
- 不自研标注工具核心算法（复用 LabelImg/CVAT 格式，网页内简化标注）
- 不做 React 前端（纯 HTML）
- 不做多租户/权限/计费/企业 SSO
- 不做实时视频流识别（仅静态 zone 图）
- 不做模型自训练流水线（MVP 使用已有自训权重）
- 不做移动端 App

## 9. 时间线 & 里程碑（来源：路径 / roadmap-planner）

### 9.1 精化时间线（按周）

**第 1 周 · 数据管线与可行性门禁**
交付：网格裁剪（R2，c1/c2 双模式）、YOLOv13n 加载骨架（R3）、首批量产级屋顶影像与 zone 切片（约 42 网格/zone）。
负责人：开发者（搭建管线）、飞手（采集影像）。
风险：CPU 推理可行性未实测，若不可行需回退 GPU 方案 [假设]；首飞影像遮挡影响标注可用性。

**第 2 周 · 核心推理与标注闭环**
交付：网页标注工具（R1）、推理+NMS 去重（R3/R4）、坐标映射打通；锁定 IoU NMS 阈值（建议 0.45）。
负责人：开发者（推理/映射）、操作员（标注）。
风险：标注一致性波动；阈值初值偏移致误检/漏检。

**第 3 周 · 交付物导出**
交付：标注图 PNG（R5）、JSON 导出（R6）、HTML+PDF 报告（R8）；固化最小 3 类定义（绿植/水桶/花盆示例待确认）。
负责人：开发者（导出管线）、操作员（标注回流）。
风险：报告字段与监测方口径不一致；类别边界模糊。

**第 4 周 · 实时面板与可配置化**
交付：实时监控面板（R7）、参数可配置化（R11）。
负责人：开发者（面板/配置）、监测方（验证可用性）。
风险：免费云冷启动/超时影响实时性；面板刷新时延。

**第 5 周 · 免费云部署与待复核**
交付：Hugging Face Spaces / Render 部署（R10，0 成本）、待复核机制（R9）。
负责人：开发者（部署）、监测方（UAT）。
风险：免费套餐内存/超时上限触发重启；域名与可用性。

**第 6 周 · 内测与参数冻结**
交付：内测版本、屋顶判定阈值（10% vs 50% 冲突）拍板、全部参数固化。
负责人：全员（内测）、监测方（口径确认）。
风险：冲突阈值未达共识将动摇监测结论可信度。

**正式上线阶段（标注后期）**
MVP 稳定、参数全部固化后，启动 P2（R12 历史趋势对比、R13 半自动屋顶预选、R14 密度热图）与企业组件升级（PostgreSQL、S3、监控），周期约 4–6 周 [假设]。

### 9.3 优先级与参数拍板窗

按"影响链路广度 × 冲突程度"排序，最晚固化时点：
1. **CPU 推理实测可行性** — 第 1 周末（门禁，决定 MVP 是否成立）[假设]。
2. **网格尺寸 grid640/step576（约 42 网格/zone）** — 第 2 周中（影响裁剪与坐标映射稳定性）。
3. **IoU NMS 阈值（建议 0.45）** — 第 2 周末（影响去重与标注质量）。
4. **置信度线** — 第 3 周末（影响 R5/R6 输出量与误检比）。
5. **屋顶判定阈值（10% vs 50% 冲突）** — 第 6 周（内测前必须锁定，冲突最高，监测方拍板）。

P0 随 W1–W4 落地即具备，P1（R9/R10/R11）于 W4–W5 收口，P2 延后至正式阶段。
