# 无人机 + YOLOv13n 屋顶蚊媒孳生容器识别平台 — 简化版 MVP 功能规格书（PRD）

> 版本边界：简化版 MVP（非完整商用系统）。砍掉企业组件：PostgreSQL→SQLite；S3→本地/免费云存储；删除缓存/队列/监控；前端用纯 HTML 而非 React。部署：现阶段免费云（Hugging Face Spaces / Render，0 成本）。模型：YOLOv13n 自训，PyTorch 加载，假设 CPU 可跑（待实测）。

## 1. 产品目标（三个清晰、正交的目标）

- **G1（效率）**：将单 zone 处理的人工作业时间从"手动标屋顶数小时"压缩到"网页内快速标注 + 一键处理 < 15 分钟" [假设，来自用户研究痛点]。
- **G2（闭环可信）**：在免费云上提供"上传→处理→复核→多格式报告→实时监控"一站式闭环，每个低置信框带"待复核"状态，结果可追溯。
- **G3（域专属精度）**：YOLOv13n 自训模型针对城中村密集屋顶适配，首版以置信度双线（高>0.8/低<0.5）输出可验收检测结果，并为趋势分析预留 zone_id + 时间戳。

三者正交：G1 关注操作成本，G2 关注流程与信任，G3 关注识别质量与数据资产。

## 2. 用户故事（场景）

- **US1（飞手）**：作为无人机飞手，我在 80m 高度按 zone 编号系统俯拍城中村屋顶，传输图像后能在网页看到"已接收"状态，确保不丢数据、参数标准化。
- **US2（操作员）**：作为平台操作员，我在一站式网页内用简化标注框出屋顶范围 → 点"提交任务" → 通过实时进度面板观察处理 → 对低置信框标记"待复核/确认" → 下载标注图与报告，尽量少手动。
- **US3（监测人员）**：作为疾控/街道监测员，我打开 HTML/PDF 报告，一眼看到高风险 zone 与高密度网格，依据标注图定位现场清理点，报告可打印/转发。
- **US4（研究生/MVP 开发者）** [假设]：作为兼任开发的操作员，我能在 README 指导下于本地或 HF Spaces 一键部署跑通整条链路。

## 3. 用户研究洞察（来源：用户研究；标 [假设]）

- 三类角色：飞手（采集）、操作员（处理，核心使用者）、监测人员（决策）。[假设，无一手调研数据]
- 最大瓶颈：手动标屋顶最耗时易错（城中村屋顶密集不规则）。[假设]
- 工具链割裂：标注本地 / 识别云 / 报告网页分处不同工具。[假设]
- 缺"待复核"机制，结果可信度依赖人工全量复核。[假设]
- 缺趋势与历史对比能力。[假设]
- MVP 启示：压缩标屋顶成本（最简网页内标注或半自动预选）；一站式闭环；决策方语言报告；标注待复核；JSON 预留 zone_id + 时间戳为趋势留接口。[假设]

## 5. 数据依据（来源：数据分析；含冲突参数）

**确定性参数（PRD 阶段先定死）**：H=80m；原始图 4000×3000；单 zone 覆盖 120×90m；GSD≈3cm/像素（自洽，120m/0.03=4000px ✓）；置信度双线（高>0.8/低<0.5）；最小 3 类（绿植/水桶/花盆，示例待确认）；输出物全包含。

**派生指标 [文档设计值]**：单 zone 网格数（grid 640, step 576）→ cols=7, rows=6, 共 42 网格/zone，重叠率 10%；单网格地面足迹 19.2×19.2m，小容器（<6–9cm 实物）有漏检风险需实测。

**冲突/待确认参数**：
- 网格尺寸 640×640（配 YOLO）vs 800×800（暂定）[冲突]
- 屋顶判定阈值 ">50%→c1" 但括号写 "10%？" [冲突]
- IoU 去重 0.3–0.5（打？？？待确认）
- 置信度过滤中间值未给（文档仅给双线阈值，0.5–0.8 之间如何处理待确认）
- CPU 推理可行性（暂定，待实测）
- 真实 GSD / 相机型号（待确认）

**必须固化最小参数集（下一步拍板）**：①网格尺寸 640 或 800；②屋顶判定阈值 50% 或 10%；③IoU NMS 建议先 0.45；④置信度线低 0.5 高 0.8；⑤CPU 推理实测；⑥真实 GSD/相机型号；⑦最小类别是否锁 3 类。建议：网格尺寸/重叠/IoU/屋顶阈值做成可配置项，首版用建议值跑通，真实数据回灌后调优；IoU 与屋顶阈值属冲突项，必须首版内测前锁定。

## 6. 需求池（P0/P1/P2）

| 编号 | 需求 | 优先级 | 验收标准 | 估算 |
|---|---|---|---|---|
| R1 | 网页内屋顶简化标注（多边形/框） | P0 | Given 操作员上传 zone 图，When 框出屋顶范围，Then 生成 roof polygon JSON 且可被网格裁剪复用 | 3 人天 |
| R2 | 一键提交任务 + 自动网格裁剪(c1/c2) | P0 | Given 标注完成，When 点提交，Then 按可配置参数生成 c1/c2 网格与 grids_metadata.json | 3 人天 |
| R3 | YOLOv13n 推理（PyTorch 加载，CPU 优先） | P0 | Given c1 网格，When 推理，Then 输出带坐标/置信度/标签的检测 JSON | 4 人天 |
| R4 | 坐标映射 + NMS 去重合并 | P0 | Given 网格结果，When 映射回 zone 坐标，Then IoU>阈值去重，输出 zone 级去重结果 | 2 人天 |
| R5 | 标注图生成 (PNG) | P0 | Given zone 结果，Then 原图叠加检测框+统计，输出 {zone_id}_annotated.png | 1.5 人天 |
| R6 | JSON 数据导出（含 zone_id+时间戳） | P0 | Given 完成，Then 输出结构化 detections/statistics JSON，预留趋势接口 | 1 人天 |
| R7 | 实时监控面板（进度/状态） | P0 | Given 任务进行，When 查看面板，Then 实时显示当前步骤与进度百分比 | 3 人天 |
| R8 | HTML + PDF 报告（决策方语言） | P0 | Given 完成，Then 生成含标注缩略图/图表/统计表的可打印报告 | 3 人天 |
| R9 | "待复核"机制（低置信框标记） | P1 | Given 检测框<0.8，When 操作员复核，Then 状态可置"待复核/确认"并留存 | 2 人天 |
| R10 | 免费云部署（HF Spaces/Render） | P1 | Given 代码，When 部署，Then 0 成本公开访问，一键跑通链路 | 2 人天 |
| R11 | 参数可配置化（网格/重叠/IoU/阈值） | P1 | Given 配置文件，When 调整，Then 处理使用新参数且界面可见 | 1.5 人天 |

## 7. 关键流程图 / UI 设计稿

端到端流程（MVP 纯 HTML 单页）：
```
飞手拍摄 → [传输/上传] → 网页标注屋顶(R1)
  → 一键提交(R2) → 实时面板(R7)
       ├─ 网格裁剪 c1/c2
       ├─ YOLOv13n 推理(R3)
       ├─ 坐标映射+NMS(R4)
       ├─ 标注图(R5)+JSON(R6)
       └─ 复核低置信框(R9)
  → 报告 HTML/PDF(R8) → 监测人员决策
```
页面结构：①上传页（zone 图 + 元数据）②标注页（画布 + 工具栏）③进度面板页（步骤条 + 百分比）④结果页（标注图 + 待复核列表 + 下载按钮）⑤报告页（报告嵌入 + PDF 下载）。

## 8. Non-goals（明确不做什么）

- 不建 PostgreSQL/Redis/队列/监控系统（改用 SQLite + 本地/免费云存储 + 进程内状态）
- 不自研标注工具核心算法（复用 LabelImg/CVAT 格式，网页内简化标注）
- 不做 React 前端（纯 HTML）
- 不做多租户/权限/计费/企业 SSO
- 不做实时视频流识别（仅静态 zone 图）
- 不做模型自训练流水线（MVP 使用已有自训权重）
- 不做移动端 App

## 9. 时间线 & 里程碑（初步，路线图规划师后续细化）

- **M1（第 1–2 周）**：R1–R6 核心链路跑通（本地）
- **M2（第 3 周）**：R7 实时监控面板 + R9 待复核
- **M3（第 4 周）**：R8 报告 + R10 免费云部署 + R11 参数配置
- **M4（第 5 周）**：首版内测，锁定 IoU/屋顶阈值冲突参数，真实数据回灌
- **P2（第 6+ 周）**：R12/R13/R14 按反馈排期

## 10. 待确认问题（汇总）

1. 网格尺寸 640 还是 800？（数据 C 冲突）
2. 屋顶判定阈值 50% 还是 10%？（数据 C 冲突；影响 c1 量级：10%→c1>80%，50%→边缘落 c2）
3. IoU NMS 阈值最终值（建议 0.45）
4. 置信度过滤中间值（0.5–0.8 之间保留/丢弃？）
5. CPU 推理可行性实测（决定部署形态与超时策略）
6. 真实 GSD / 相机型号（影响 GSD 3cm 假设）
7. 最小类别是否锁 3 类（绿植/水桶/花盆为示例待确认）
8. 飞手→平台传输在 MVP 是否仅支持 USB/上传，无线/云传推迟？

【需求视角 · 范围边界判断】
- **必为 P0（构成 MVP 闭环与可验收交付物）**：R1 网页标注、R2 网格裁剪、R3 推理、R4 去重、R5 标注图、R6 JSON、R7 实时面板、R8 报告——直接对应交付物"标注图 + JSON + HTML + PDF + 实时面板"全包含；用户研究最大瓶颈（标屋顶）须首版具备，闭环可信依赖面板 P0。

- **P1 取舍**：R9 待复核、R10 部署、R11 参数可配置建议保留为 P1——"可信"与"免费云验证"是差异化与首版内测前提；若工期极紧，R10 可先本地验证、部署延至 M3 末。
