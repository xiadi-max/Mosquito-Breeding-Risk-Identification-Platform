# v2.2 前后端联调清单

## 1. 联调原则

当前 `index.html` 已有完整视觉和演示交互。联调采用“接口逐项替换模拟逻辑”，不重写 UI：

- 先用兼容 dashboard 替换 `TEST_DATA`；
- 再按七个阶段逐个替换 `setInterval/setTimeout/toast` 假动作；
- 每完成一段就保留可用页面；
- demo 与 production 明确分开，网络错误不自动假成功；
- 前端持有真实 `task UUID`，不再用任务名称或 `T-0716` 识别任务。

## 2. 第一阶段：Dashboard 冒烟

修改 `data.js` 时保留双模式：

```js
window.APP_CONFIG = {
  dataMode: 'api',
  api: {
    baseUrl: '/api/v1',
    dynamicDataUrl: '/api/mosquito-workbench/dashboard'
  }
};
```

验收：

- [ ] 通过 HTTP 服务打开，不能用 `file://`；
- [ ] dashboard 200，任务卡片/当前任务/ROI/复核/热点能渲染；
- [ ] 空数据库显示空状态而不是 JavaScript 崩溃；
- [ ] 500/网络断开显示可重试错误；
- [ ] `test_data.js` 只在 demo 模式加载或使用，不污染 production。

## 3. 统一前端 API 客户端

不要在每个 onclick 里散落 fetch。新增一个小型 `api.js`：

```js
export async function apiFetch(path, options = {}) {
  const requestId = crypto.randomUUID();
  const headers = new Headers(options.headers || {});
  headers.set('Accept', 'application/json');
  headers.set('X-Request-ID', requestId);
  if (options.body && !(options.body instanceof FormData)) {
    headers.set('Content-Type', 'application/json');
    options.body = JSON.stringify(options.body);
  }
  const response = await fetch(path, {...options, headers});
  if (!response.ok) {
    const problem = await response.json().catch(() => ({
      title: '请求失败', status: response.status, request_id: requestId
    }));
    throw problem;
  }
  if (response.status === 204) return null;
  return response.json();
}
```

生产代码还需：请求取消、超时、对按钮恢复状态、统一 problem toast/错误面板。写操作不要自动无限重试；幂等作业在相同 `Idempotency-Key` 下允许一次受控重试。

## 4. Task 替换

### 新建

`createTask()`：

1. 前端基础必填校验；
2. `POST /api/v1/tasks`；
3. 使用响应真实 `id/code` 创建卡片或重新拉取列表；
4. 设置 `currentTaskId`；
5. 进入 Step 1。

不要用 `T-${MMDD}`，同一天可能有多个任务。

### 选择

任务卡 `dataset.taskId` 存 UUID。选择时请求：

```text
GET /api/mosquito-workbench/dashboard?task_id={uuid}
```

重新渲染该任务的影像、ROI、进度、复核、结果。选中状态属于浏览器 UI，不要保存“全系统当前任务”到服务端。

### 删除

确认文案应说明任务影像和结果将删除。如果后端返回 deletion job，卡片显示“删除中”，完成后移除；失败允许重试。

## 5. 上传替换

文件选择器的 `accept` 必须限制为 `.jpg,.jpeg,.png,image/jpeg,image/png`。页面在少于 2 张有效影像时禁用“进入拼接”和“开始自动拼接”，服务端仍做最终校验。

当前 `loadFiles()` 把任何文件显示为 `GPS READY`，真实联调必须改为使用服务端返回：

- accepted：绿色通过；
- warnings：例如无 GPS/无拍摄时间；
- duplicates：说明已存在；
- rejected：显示 MIME、尺寸或解码错误原因。

大批上传时显示真实字节上传进度需要 XHR 或分文件请求；原生 `fetch` 没有通用 upload progress。MVP 可以按文件逐个/有限并发上传，UI 聚合进度。失败可针对单文件重试。

`resetUpload()` 不应只清空 DOM。调用 DELETE，并在已有下游结果时显示将失效的范围。

## 6. 拼接 + SSE

当前拼接语义为 OpenCV SCANS 仿射配准，不再展示伪造的“覆盖率/平均重叠率”。质量区展示策略、工作尺度、GPS 数量和异常影像数；成功后从受控 Artifact Endpoint 读取真实 JPEG，并同时放入拼接预览和 ROI 背景。

替换 `startStitch` 的计时器：

```text
POST /api/v1/tasks/{taskId}/mosaic-jobs
Idempotency-Key: mosaic-{taskId}-{imageSetFingerprint}
```

得到 `links.events` 后连接 EventSource：

```js
function watchJob(job) {
  const source = new EventSource(job.links.events);
  source.addEventListener('job.progress', event => {
    const data = JSON.parse(event.data);
    updateProgress(data.progress, data.message);
  });
  source.addEventListener('job.succeeded', async event => {
    source.close();
    await reloadCurrentTask();
  });
  source.addEventListener('job.failed', event => {
    source.close();
    showJobFailure(JSON.parse(event.data));
  });
}
```

浏览器原生 EventSource 会自动重连并发送 last event id。页面刷新后从任务详情找到 running job 再重连。若 SSE 失败多次，降级轮询 `GET /jobs/{id}`。

拼接图 `<svg>` 演示背景已由 artifact JPEG 的 Blob URL 替换。保持 zoom/pan 交互，页面销毁或重新生成时释放旧 Blob URL；不能把服务器磁盘路径写入 DOM。

## 7. ROI 与坐标换算

现有 `svgPoint()` 返回 900×545 viewBox 坐标。保存前转换到 mosaic native pixel：

```js
function svgToNative([x, y], mosaic) {
  return [x / 900 * mosaic.width, y / 545 * mosaic.height];
}

function nativeToSvg([x, y], mosaic) {
  return [x / mosaic.width * 900, y / mosaic.height * 545];
}
```

注意当前 `getBoundingClientRect()` 算法在 `preserveAspectRatio=meet`、留白和 CSS transform 下可能产生偏移。联调时应优先使用 `SVGPoint` + `getScreenCTM().inverse()` 把 pointer 映射到 SVG user space，再做 native 换算。

保存：`PUT /tasks/{taskId}/rois`，携带 `expected_version` 和 `source_artifact_id`。收到 409 时提示“范围已更新”，刷新后让用户重新确认，不能静默覆盖。

## 8. Grid 预览

当前 `renderGrid()` 使用静态 `tileWidth=300/tileHeight=260` 画展示格，这不是实际 640 pixel 网格。改为：

1. overlap slider 变更后做 200–300ms debounce；
2. `POST /grid-plans/preview`；
3. 后端返回 native source boxes；
4. 前端按 mosaic→当前 `900×520` viewBox 缩放绘制；
5. 预计网格、有效网格、padding、数据量全部使用后端值；
6. 点击“生成网格并推理”先 `PUT grid-plan`，等待成功后再创建 inference job，或由后端编排成受控复合作业。

不要使用前端估算结果作为推理输入。

## 9. Inference 与复核

`runModel`：创建 inference job，按 `job.step` 更新四个 pipeline 节点：

| 后端 step | 前端节点 |
|---|---|
| `load_model/load_tiles` | 载入模型与网格 |
| `detect` | 目标检测与类别识别 |
| `map_coordinates/class_aware_nms` | 跨网格去重与坐标还原 |
| `persist/build_review_queue` | 低置信度结果筛选 |

完成后请求 pending reviews。每个 review 应显示后端 crop artifact，不再用空 `.review-img`。

`resolveReview` 调 PATCH；请求期间禁用两个按钮。成功后使用服务端返回的 pending count 和有效总数，避免 DOM 自己减计数。409 时刷新该 detection。

## 10. Risk 结果

阈值 slider 调整目前只改标签。真实流程中：

- 拖动时只做前端预览/显示值；
- 用户点击“重新计算”后 POST risk run；
- risk job 完成后替换 hotspot、类别统计、指标和 density artifact；
- canonical polygon 转 SVG path 可在前端完成，或兼容层返回展示 path；
- 聚集等级颜色、gradient 仍在 `data.js/CSS`；后端返回 `clustering_level/clustering_index`，不返回 CSS。

若 pending review > 0，可允许预分析但必须标 `provisional=true`；推荐 MVP 阻止正式风险报告并告诉用户先完成复核。

## 11. AI 建议

`generateAi`：

1. context 长度限制并纯文本提交；
2. POST decisions；
3. 显示真实 job 进度；
4. 返回结构化 priorities 后安全构造 DOM；
5. 不用 `innerHTML` 插入 provider 原始文本；
6. 保存编辑时把 DOM 解析为结构化字段或发送经过 allowlist 清洗的内容；
7. 版本与生成时间使用服务端值。

每版固定显示 disclaimer；服务端 evidence refs 可点击/悬停映射到热点和阈值。

## 12. 导出

三个按钮均创建 export job。按钮状态：

```text
可用 → 正在生成 → 下载
               ↘ 失败/重试
```

成功后使用 artifact URL。不要通过前端 Blob 伪造“后端报告已生成”。PDF 下载名称可由 `Content-Disposition` 提供，避免前端拼接不安全任务名。结果页必须解释 H01/H02 是按聚集指数排序的区域定位编号、白色虚线是近似外包边界；PDF 必须复用同一风险快照生成带编号定位图，保证正文代号可回到图上定位。

## 13. UI 状态必须来自后端

| 状态 | 当前原型 | 联调后 |
|---|---|---|
| 完成度 | `goStep` 访问页面即增长 | 后端已成功产物派生 |
| 当前任务 | 卡片 `dataset.task` 名称 | UUID + dashboard |
| 上传通过 | 默认所有文件 GPS READY | 服务端校验结果 |
| 拼接进度 | `setInterval` | persisted job events |
| 推理结果 | `setTimeout` + 36 | inference run |
| 复核计数 | DOM 计数 | API effective state |
| 目标聚集指数分界 | 只修改 DOM | 新 risk run/version，并与区域卡片的 clustering_index 同口径 |
| AI 版本 | 固定“版本 1” | decision version |
| 导出 | toast | export job + artifact |

## 14. 断网、刷新与重复点击

- 页面加载后先查询任务和 running jobs；
- running job 自动恢复订阅；
- 所有作业按钮提交后立刻禁用，收到 202 保存 job id；
- 网络超时但未知是否已创建时，用相同 Idempotency-Key 重试；
- SSE 断开不等于 job 失败；先重连/轮询；
- 只在服务端明确 terminal failed 时显示失败；
- 浏览器刷新不清空任何后端数据。

## 15. 联调完成定义

- [ ] `dataMode='api'` 下不读取 `TEST_DATA`；
- [ ] 全部 `setInterval/setTimeout` 假业务已替换（toast 动画除外）；
- [ ] 所有按钮都有 loading/success/error/retry 状态；
- [ ] 页面刷新、任务切换、API/Worker 重启后状态一致；
- [ ] DOM 中不出现本机绝对路径、密钥或未清洗 HTML；
- [ ] ROI、grid、detection、hotspot 在不同缩放/全屏下位置一致；
- [ ] 当前 UI 的 5 类、阈值和后端 model metadata 一致；
- [ ] 错误消息包含可供排查的 request id；
- [ ] 端到端 Playwright/浏览器测试覆盖 happy path 与至少一个失败重试路径。
